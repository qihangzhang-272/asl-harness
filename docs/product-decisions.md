# ASL 核心产品决策

> 记录用户明确确认的产品方向，最新在前，每次口述追加一条极简要点；不把设想写成已完成。实现与验收状态唯一见 [总体架构与专项视图](asl-architecture-views.md#view-9--当前项目状态)。

## 2026-10-04 · 本轮发布与 Agent 改动范围

**本轮发布 App 与 CLI；维护 Agent 仅负责拉取完整技能、填写 Mode 的引用并转化为节点，可调整 Mode 组织形式，严禁改写技能内容。** 其他 Agent 的合规成果直接保留；只修正有证据的规范遗漏。现有未确认发布的业务修改不随程序上传。

## 2026-10-04 · 鼠标优先的新建与编辑

**画板右键选择模板新建，左键／双击原位编辑，拖拽调整 Mermaid 结构；用户不必写语法或记组合键。Agent 与用户共编同一原文，实际渲染与协议检查通过才生效。** 沿用现有视觉和画布，不新增常驻编辑按钮、自由坐标真源或专有模板协议；历史待办归并到当前计划。

## 2026-10-02 · 零配置阅读与连续体验

**只有 App、尚未配置 Agent 的用户，也应能发现本机已有技能或模式库、直接阅读公共 GitHub 内容。默认呈现图文，原文按需打开；检查重开、刷新、返回和切换的一致性，不把用户举例当成已确认故障。** 保留高级编辑和本地写入门控，不增加全盘扫描或另一套配置流程。

## 2026-10-02 · 收敛已有实现

**新建和已有 Mode 共用原生 Mermaid 编辑页；按 Ponytail 退役重复画布、缩减主界面职责，保留写入门控。** 桌面验收入库，加载先测量，当前状态与历史分开；仅清理已核对并批准的冗余目录，不扩大到业务内容。

## 2026-10-02 · 原生多图型与统一可读性

**技能协作可以用 Mermaid 流程、时序、状态、思维导图等原生语法表达；沿用已有架构图的字体、配色、线条与画布交互，不另建视觉体系。** 可读性是验收项：默认字号、标签对齐、连线密度、分组及普通窗口下的浏览都要检查，不为展示复杂度堆关系；渲染成功不等于关系清晰或所有图型均可任意拖拽编辑。

## 2026-10-02 · 唯一本地内容库

**本机只保留一套日常使用的技能与 Mode 真源，直接对应 GitHub；不强制用户维护 Personal Harness 与公开内容库两套重复体系。** GitHub 表示已发布版本，本地修改经检查后再提交发布；历史副本先核对独有内容和引用再清理。框架与 App 代码不混入技能内容库。具体合并、删除及部署状态见总体状态，不以该决定冒充迁移已经完成。

## 2026-10-02 · 连续画板与就地操作

**技能在主区域打开，同一张 Mermaid 图缩小后悬浮在右上层，仍可选节点，随时恢复完整画板；不拆成互斥页面。添加技能从画板右键进入，全屏继续编辑同一原文。** 仓库内文档与语言切换留在 App，已知来源后台预读；安装到哪个 Agent 就留在该 Agent，不要求另选配置者。

## 2026-10-01 · CLI 同源管理与架构分块

**Agent 和 App 共用现有 Harness CLI；正式修改先通过协议与实际渲染门控，失败反馈后修正重提。Harness 是框架，Skill Library 是内容版，机械同步但不复制实现；专项视图分文件管理，总览保留唯一当前状态。** 集中的是管理入口，不合并独立 Environment，也不新增服务、数据库或第二调度器。

## 2026-09-30 · 点击即编辑（历史口述）

**点击节点，直接在原位置修改文字；不弹文本框，不先点编辑按钮。回车或离焦保存，Esc 取消；右侧只呈现选中技能的真实文件。** 图上编辑的是 Mermaid 标签，不静默改写技能正文。云端连接可右键移除；更新 Agent 内容须留在原宿主、原位置。

## 2026-09-30 · 原生图与按需技能侧栏

**不采用本轮三张生成稿。中心直接渲染 Mermaid，并支持可视化修改后写回原文；右侧仅承载选中节点的真实 Skill 正文、脚本与内部架构，支持双击编辑，不堆冗余功能。** 图型编辑范围必须按真实实现说明，不能以代码预览冒充所有图型的双向可视编辑。

## 2026-09-30 · 先完成可用闭环，再用视觉方案定方向

**工作图使用原生 Mermaid 的清晰表达；完成当前修复后，以 Taste Skills 审查和生图探索提升视觉。只给模型核心业务与浅蓝半透明的边界，保留设计自由，不把长篇解释塞进产品。** 视觉方案须经选择再落地，不将生成效果图当成已实现界面。

## 2026-09-29 · 原生图示与写入反馈（最新口述）

**工作架构直接使用本地 Mermaid 原文与官方渲染；用户和 Agent 共编。新增、替换或导入时必须实际渲染成功，失败须把定位信息和重写要求返回写入 Agent，修正后重试，不能仅标记错误或覆盖有效文件。**

支持当前安装 Mermaid 版本的原生图型，不限流程图。Mode 表达完整技能的协作，Skill 内图表达有原文依据的核心问题与思路；不凭空补画。通过同一 CLI 调用回传反馈，不另设模型调度器；直接绕过接口修改磁盘文件，不能保证自动联系原宿主会话。

## 2026-09-29 · 仓库浏览连续性

**连接 GitHub 后先呈现 README；仓库内的技能列表、详情和返回都留在所选仓库，不跳到全局发现。分类入口呈现对应范式图，而不是重复技能列表。**

## 2026-09-29 · 本地采用与云端浏览（最终口述）

**公共 GitHub 仓库以云端为真源，可直接在线呈现，无需先保存；采用到本地的 Mode 以本地持续使用、修改和培养的版本为唯一真源，上游更新不直接覆盖 Mode。**

本地优先适用于所有已拉下来、进入本地管理的 Mode；公共项目可以只连接和浏览，不要求建立本地工作副本。解析缓存不等于采用，也不成为真源。

库可跟踪多种来源；本地 Mode 在云端能力、技能与真实场景的组合中持续演进，没有固定不变的初始模板。文件与已有数据库中的业务数据都开放给人和 Agent，经协议校验后生效。Mode 可经授权独立发布到 GitHub；发布不改变本地工作版本的真源地位。以下较早记录若有歧义，以本条为准。

## 2026-09-29 · 库与 Mode 独立演进（最新修正）

**库负责追踪与同步来源，Mode 负责组织和培养工作环境；开放本地文件及已有数据库的业务数据给 Agent，通过同一校验入口修改与呈现，不将两者的更新混为一谈。**

可追踪多个云端仓库并将更新同步保存到本地；库的模型与版本独立于本地 Mode，不能用上游更新直接覆盖用户培养的模式。Mode 可独立变更，也可由用户授权 Agent 发布到 GitHub 供人采用。不为「开放数据库」而新增一套数据库；已有存储提供受控读写接口，秘密、账号、受管指纹与校验实现不作为任意可编辑业务内容。

## 2026-09-29 · 本地优先、开放接入、严格验收

**做 AI 时代的 Obsidian：用户的技能、Mode、场景范式和资料保存在本地，人和 Agent 共编；通过协议验收才进入 App 正式展示与宿主配置。** 原先「本地文件是唯一内容真源」的限定已被上方最新决策修正，已有数据库也属于开放编辑面。

目标接入 WorkBuddy、千问办公、豆包工作、Codex、Claude Code、OpenCode、Cursor 及 DeepSeek Harness。逐个核实原生接入能力，不承诺尚未验证的兼容；支持云端库更新同步与本地保存，Mode 自身演进独立管理。错误精确到文件或字段，保留有效内容与修复入口；不因一个错误让整个界面不可用。

## 2026-09-29 · 中间平台与工作场景

**ASL 是连接个人工作环境与 AI 应用的中间平台：以开放 Harness 协议加载完整技能，在其上组织可编辑、可迁移的 Mode 和工作场景范式。**

Mode 围绕工作目的，不围绕人的身份；范式表达技能如何协作，不是强制的线性工作流。业务仍由当前 Agent 执行，ASL 管理内容、校验和接入，不另造执行器。

## 2026-09-29 · 兼容已有生态

**不要求外部仓库先遵循 ASL：常见 Skill、Agent 指令与插件仓库先识别，再由用户使用的 AI 按 ASL 整理为 Mode。**

「交给 AI 整理」携带工作目的、只读来源、写入位置及当前协议；保留完整包、必要来源与许可，标明未配依赖。整理后校验、展示、继续编辑。普通用户不需要先理解这些技术名词。
