# 历史、归档与 Agent 使用体验收束

> 2026-10-08。用户已授权本轮实现；计划只记录范围与证据，项目当前状态仍以总览 View 9 为准。

## 已确认的取舍

- 暂缓偏好影响扩展与技能培养、候选、试用、效果评分；不为这些目标增加页面。
- 历史与 Agent 决定回顾保持轻量：复用 Git 与已有明确文字记录，不采集内部推理，不新建日志引擎、数据库、事件总线或另一个 Harness。
- Mode 手动保存需要可见的 Git 版本与回退。仅处理 Mode 组织文件，不自动提交 Skill、个人资料、其他 Agent 或用户的未提交改动；回退产生新记录，不重写旧历史。
- 后续 Agent 读取真实变更后补充明确说明，不后台启动 Agent，不伪造修改意图。
- **最新视觉决策：**Git 只在后台；前端是一条带版本节点的细演进轴与同一张架构画板。拖动定位、主动回放，图上呈现节点与连接变化；拒绝上方历史缩略图、Git 提交列表主界面和另起编辑体系。恢复与继续编辑分开，拖动回看不写盘。
- 归档提供浏览、恢复和专门的清理入口。清理逐项预览、明确确认、移到系统回收站；不定时清空，不永久删除，不处理来源不明的目录。
- 本轮先完成框架、App、隔离测试和架构文档，不操作真实业务内容、账号、宿主投影或试用窗口。用户另已授权后续同步 GitHub 与跨平台包，随后明确先继续当前工作；本阶段不抢先打包发布或替换桌面。

## 产品与文案约束

沿用现有浅蓝视觉和现有阅读、列表、分栏组件。用户看到的是任务与结果，不是内部实现说明。正常状态只保留短标题、具体动作与必要结果；路径、原始错误和实现细节按需展开。删除、回退等风险不得用精简文案掩盖。主操作面静态提示以不超过 100 字为目标，用户正文、文件差异及展开后的详情不截断为口号。

依据：[Apple Writing](https://developer.apple.com/design/human-interface-guidelines/writing)、[Google Workspace UI 文案](https://developers.google.com/workspace/add-ons/guides/workspace-style)、[Material UX Writing](https://codelabs.developers.google.com/codelabs/material-communication-guidance)。采用其简洁、统一、行动明确、错误可恢复和熟悉控件的原则，不另换一套视觉体系。

## 实施与验收

1. **归档底座与窗口**：复用原归档目录及同一 CLI；列出内容、原位置与恢复动作。先测未知格式、冲突、链接越界、外部修改和非法图，恢复保持原字节。清理预览给出精确路径与体积，取消无副作用。
2. **演进时间轴与 Mode 回退**：单画板、条状演进轴，拖动切换真实历史结构，主动播放依次回看；复用 Mermaid 原生渲染与现有样式，同身份节点短时位移，新节点进入，减少动态效果时取消空间运动。相邻记录预读、近期绘图结果有界复用，快速拖动只跟进最终选择，不排长渲染队列。手动保存写入 Git 快照，保留现有暂存区与分支；恢复前校验当前指纹与预览，成功后显示新记录。继续编辑进入既有草稿页，不直接覆盖。无 Git、无记录、失败不可冒称成功。
3. **轻量说明**：Agent 的说明附着于原提交，而非新建业务系统；已有人工文档保留但不强迫用户填写反馈表。对新增说明执行并发保护，不篡改原作者与提交。
4. **Agent 配置体验**：核对、补齐、查看结果留在同一宿主；技术诊断折叠、缺项与下一步可见，失败重试对应原操作。Hook 只显示已取得的证据，不将命令存在当作触发成功。
5. **统一收束**：主控整合入口与简洁文案，补端到端隔离回归、检查实际页面、更新总体与专项视图。功能完成、开发验收、发布三种状态分别记录。
