# 鼠标优先的 Mermaid 画板收敛计划

> 依据：2026-10-04 用户明确要求，延续已确认的「结构编辑、原生排版」方向。按下列步骤顺序实施，不另建画布引擎。当前完成度与发布状态只维护于[总览 View 9](../asl-architecture-views.md#view-9--当前项目状态)。

> 后续实测纠偏：此轮模板和结构排序已交付，但流程图声明排序没有满足用户要求的直接拖动；四面控件也没有保留端口身份。后续按[直接操作补齐计划](2026-10-04-canvas-direct-manipulation.md)执行，不把旧验收表述为自由拖拽已完成。

## 目标与取舍

用户无需编写语法，即可新建图、增减元素、改字、调整协作结构。图继续是 `MODE.md` 中的 Mermaid；成员身份继续由现有 Mode 协议维护。普通结构节点不冒充 Skill，添加真实技能仍经过成员归属检查。

- 空白处右键新建流程图、思维导图或时序图；选择即产生可编辑草稿，不覆盖已有图。
- 左键选择、双击原位改字；右键增减和连接；拖动改变顺序或父子关系。菜单按目标呈现，不增加常驻编辑工具条。
- 思维导图以节点上沿／中部／下沿表示排在前面／作为子节点／排在后面，无需 Shift。
- 时序图参与者左右排序，消息与备注在同一分支内排序；通过点选参与者新增消息，右键增减备注和条件分组。条件块整体移动，不能误把一半条件搬走。
- Agent 使用相同 Mermaid 文本和现有 CLI；不引入模板数据库、第二份坐标、业务调度器或自动模型任务。
- 所有新模板元素均须完成鼠标闭环。其他 Mermaid 图型继续原生渲染；无法无损映射的复杂语句保留且明确拒绝结构改写，不宣称任意图型全语法可编辑。
- 本轮只改已授权的 Harness 框架、说明与隔离测试样本；不改真实 Skill／Mode 内容，不编辑 Ponytail 技能正文。后续用户已明确授权发布与桌面替换，须通过发行验收后执行；状态只记于 View 9。受保护文件的删除仍须逐项确认。

## 第一步：收敛记录与验收范围

文件：本计划、`docs/product-decisions.md`、`docs/architecture/02d-app-navigation.md`、`06-mode-skill-architecture.md`、`docs/asl-architecture-views.md`、既有 Mermaid 计划。

1. 记录最新鼠标交互决策；旧计划标为历史入口，不保留两份待办。
2. 移除现行说明中依赖 Shift、要求先写语法建图及已失效的架构缺口描述；历史事实保留在历史记录。
3. 现有脏工作树不视为本轮产出；不自动清理技能、归档、测试证据、安装包或未知文件。

验收：链接有效；现行交互约束唯一；计划不冒充完成或发布记录。

## 第二步：模板新建与普通元素

文件：`desktop/src/mermaid-document.mjs`、`MermaidEdit.jsx`、`Architecture.jsx`、`ModeWorkspace.jsx`、对应单元与桌面测试。

1. 先测模板追加保留现有文档、重名标题、CRLF 和未知模板拒绝。
2. 在现有画板菜单加入图型选择；阅读页、编辑页、空白页复用同一入口。
3. 选择后进入新图；编辑页取消草稿不写盘，阅读页延续原位修改经门控直接保存的语义。两者均先实际渲染，再走核心门控。
4. 右键添加普通节点／参与者与真实技能分开；不为普通节点创建 Skill 文件。

验收：三种图无需输入代码即可创建；旧图与正文逐字保留；新图可保存、重开、继续修改。

## 第三步：鼠标结构编辑

文件：`desktop/src/mermaid-structure.mjs`、`mermaid-structure-dom.mjs`、`mermaid-handles.mjs`（仅必要时）、`MermaidView.jsx`、`MermaidEdit.jsx`、`mermaid.css`。

1. 先补结构测试：子树移动／同级排序／根节点保护／祖先环／重复文字／分支边界。
2. 拖放位置实时显示目标含义；取消与无效落点不修改原文。
3. 补时序消息、备注、参与者、条件块的增减与排序；按原文身份定位，不按可见标签猜测。
4. 流程图保留四面拖线和标签编辑；节点排序及方向调整写回 Mermaid，不存脱节坐标。
5. 高级语法、激活或动态生命期无法保证语义时拒绝相关结构操作，但保留安全的文字编辑与原文。

验收：全部模板元素只用鼠标可选、可改、可增减、可调整结构；键盘只用于输入内容；不破坏其他块、换行与注释。每次变更实际渲染后才接受。

## 第四步：用户与 Agent 往返、回归及文档收束

文件：`desktop/test/mermaid-*.test.cjs`、`desktop/e2e/structure.cjs`、`desktop/e2e/README.md`、上述专项视图和总览。

1. 用 Agent 风格直接写入标准 Mermaid，再在 App 中鼠标编辑并回读同一文件。
2. 三种图执行新建→改字→拖拽→右键增减→撤销／重做→保存→重开；坏图仍拒写。
3. 检查普通窗口、放大、全屏和技能悬浮视图下的标签、落点、菜单、滚动及布局。
4. 运行前端完整单测、构建、相关桌面回归和架构链接测试。正常完整性目录验收候选，不使用已知 Low 完整性构建副本。
5. 核对 diff，只收束本轮相关重复代码与文案；总览分别写清已验证、未支持、未发布。桌面替换及 GitHub 发布不是“开发通过”的同义词。

停止条件：三类模板的鼠标闭环通过，原文往返无损，写入门控未削弱。若复杂图还需语法编辑，逐项报告限制，不以渲染成功代替编辑验收。
