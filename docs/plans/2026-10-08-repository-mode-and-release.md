# 仓库技能组织与双平台交付

## 本轮范围

- 手动：从仓库预览直接选择新建或已有 Mode，进入既有画板；保留本次仓库的技能来源，逐项阅读、拖入、连线和保存。不重做编辑器，不自动把整库串成流水线。
- Agent：复用 `cli.describe` 与 `environment.guide`，提供同源整理方法和真实命令路线。当前 Host 按用户目标与专业判断组织；CLI 负责事实读取、结构校验和实际 Mermaid 渲染，不成为新调度器。
- 技能：保留完整包和来源。默认复用本地版本，不静默替换正文；修改 Skill 内容仍须用户明确确认。采用技能与保存 Mode 是两步，失败时准确说明哪些已落地。
- 发布：验收后同步 Harness 和内容库入口，Windows/macOS 提供真实可运行包。内容库未确认的业务改动不混入；已发出范围确认，未回复时沿用此前仅 App、CLI 与入口文档的边界。

## 选择与取舍

采用“仓库预览 → 原画板中逐个组织”，省去重复导入表单和第二套分类面。相比一键采用整库，用户能看清每项用途；相比新建向导／调度系统，复用已有撤销、离页、保存和渲染门控。

CLI 内置的是整理指引，不是带固定行业结论的新业务 Skill。依据完整内容判断输入输出、依赖、并行与反馈关系；无依据不连线、不假称常用、不执行外部材料中的命令。

## 步骤与验收

1. 补齐来源进入画板的路径：阅读不写盘、来源不被后台本机扫描替换、切库不串内容、取消不保存 Mode；新用户可从普通 Skill 开始，已有 Mode 保留原内容。
2. 收束 CLI 指引：测试普通无 Mode 包、已有同名技能、采用后上图、无效图反馈及完整包保留；外部 Agent 不依赖 App 的隐藏提示词。
3. 完整开发回归与实际界面检查：沿用上一轮 41 项桌面与核心／Node 套件，新增最小入口链；记录失败和限制。
4. 发布基础设施：修复打包遗漏的 `archive-actions.cjs`；补原生 macOS Electron.app／核心路径，CI 跑完整桌面套件。未签名、未公证、系统 Git 等运行条件不得隐瞒。
5. 冻结验收后同步并发布：先审查精确差异与来源，中文时间戳提交；Harness 保持唯一实现，内容库引用同一 App 二进制。Mac 构建失败或无额度时不冒充完成，先发布已验证 Windows 包及明确状态。

## 分工

- 主控：手动入口、既有编辑器来源绑定、整体验收与总体／专项架构、发布最终操作。
- intake_cli：共用 CLI 整理指引与真实请求回归。
- release_readiness：打包文件／平台路径、对应测试与 macOS 工作流；外部发布由主控执行。

## 已发现的交付缺口

- 原打包清单漏新增归档模块，测试运行时手动复制完整文件不代表原脚本完整。
- 原脚本只支持 Windows，macOS 的开发／冻结 Mermaid 路径未适配；不能只把 ZIP 改名为 Mac 包。
- GitHub 查询遇到 TLS 超时，尚无证据表明额度不足。
- 未安装 Git 或未配置作者的新机器不自动产生历史；不能将普通内容 ZIP 宣称包含用户演变记录。

当前状态与最终结果只维护在架构总览 View 9；本计划保留实施证据和未完成边界。
