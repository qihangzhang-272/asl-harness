# CLI 优先的 Mode 管理收束计划

目标：用户直接与 Agent 对话组织 Mode；App 与 Agent 读取同一关系定义，正式写入仍经过现有协议、指纹和实际渲染门控。

架构：复用 Harness CLI 和现有原生会话启动器。Mode 成员、分类与范式归属保留在 YAML；已有作者 Mermaid 时，不再把旧 YAML 连线作为另一份关系送给 Host。App 不新增聊天后端、模型账号或调度器。

技术：现有 Python 核心、Electron IPC、React 与 Mermaid；不安装依赖。

## 已确认范围

- 移除 App 中编辑、重生成和复制完整整理提示词的主路径。
- 整理入口选择已有可启动 Agent，在它的原生会话中交流；未支持原生启动的 Agent 可使用同一 CLI，不伪称已接入。
- 默认整理 Mode 组织。Agent 若需要修改 Skill 正文、脚本、资料或资产，先说明具体路径、改动和影响，取得用户明确同意后再操作。
- 用户授权属于当前 Host；CLI 公布边界，不以 Agent 自填布尔值伪造人类确认，也不声称能控制任意直接磁盘写入。
- 本轮不修改真实 Skill、Mode、账号、投影或桌面版本，不发布、不提交其他 Agent 的改动。

## 方案取舍

采用现有 CLI 与原生会话：最少移动部件，保留当前宿主权限。
不新增嵌入式 Agent 服务：避免第二执行器与账号体系。
不保留提示词编辑器作为兼容主入口：已被用户明确取消；CLI 的机器契约与内部任务材料仍可兼容调用。

## 一、关系真源

文件：`src/asl_harness/adapters.py`、`tests/test_paradigms.py`。

1. 加入作者图与旧 YAML 连线相冲突的临时环境测试，先确认失败。
2. 有作者 Mermaid 时保留组织信息，但不输出旧连线；无作者图时保留合法旧定义。
3. 验证反向边、反馈环与原生时序图不会被当成固定执行顺序或被重写。

## 二、CLI 与确认契约

文件：`src/asl_harness/commands.py`、`src/asl_harness/management.py`、`tests/test_cli_contract.py`。

1. 测试 CLI 可发现默认整理范围和 Skill 修改须经确认的边界。
2. 修正整理材料中的默认授权，不删除经用户同意可用的 Skill 编辑能力。
3. 继续返回原有错误码、定位、修正动作；不添加新的业务请求字段或假授权令牌。

## 三、直接进入 Agent

文件：`desktop/main.cjs`、`desktop/preload.cjs`、`desktop/src/EnvironmentGuide.jsx`、对应现有测试。

1. 先写 IPC 与页面测试，覆盖取消、路径边界、未知快照、无 Agent、启动失败及原生任务材料。
2. 复用已检查的来源快照与现有启动器；使用实际随包 CLI，任务材料不作为任意代码执行。
3. 页面只呈现整理目标、可用 Agent、可重试结果；没有完整提示词编辑或复制步骤。
4. 存在未保存目标时继续使用离页确认；没有 Agent 不影响原有本地和云端阅读。

## 四、文档与验收

更新核心产品决策、View 2D、2G、6 与唯一 View 9 状态。修正与这轮契约直接相关的歧义，其余旧文档和发行入口留到下一步。

依次执行针对性 Python 与 Node 测试、前端构建、隔离桌面回归、架构文档检查；使用临时库，不启动真实模型任务、不修改用户业务文件。实际宿主登录及业务调用尚未验收时如实保留限制。

完成后检查任务 diff 与业务库状态；后续打包发布单独验收，不把开发通过写成桌面已经更新。
