# CLI 同源收束实施计划

> 2026-10-01 用户已确认：扩展现有 CLI，不另建服务或数据库；Agent 和 App 共用门控，专项视图拆分。

**目标：** Agent 能发现、读取、组织和提交本地 Skill / Mode；正式写入先验收，失败不覆盖有效内容。

**架构：** `asl-harness` 是唯一实现入口。Skill Library 是共用协议和实现的内容 Environment，不复制核心代码；Personal Environment 与公开 Library 保持独立真源。App 消费同一 JSON 契约，不做第二调度器。

**技术：** 现有 Python、argparse、标准库进程锁、PyYAML 与离线 Mermaid 渲染器。无需常驻服务；含图验收仍需要随包渲染运行时，不能把纯 Python 安装冒称完整离线发行。

## 方案与约束

- 采用：扩展现有 CLI、复用包读取和写入门控。减少重复接口，保持现有宿主兼容。
- 不采用：另建后台服务、中心业务数据库或 Mermaid↔ReactFlow 全语法转换；它们不能解决已确认的门控漏口。
- 受控 CLI 能拒绝非法提交；不能阻止其他进程直接写磁盘。协作锁和异常回滚不等于断电恢复或跨文件原子可见性。
- 不改业务 Skill 方法，不合并两个 Environment，不删除已有缓存、探针或备份，不修改账号。同步发布检出是机械复制，不等于提交、推送或 Release。

## 任务一：CLI 可发现与完整文件读取

涉及：`src/asl_harness/commands.py`、`management.py`、CLI 测试及 README。

1. 写 `cli.describe`、`mode.files`、参数错误 JSON 的失败测试并运行。
2. 从 argparse 和同一操作字段常量生成契约；Mode / Skill 共用安全包读取。
3. 运行针对测试，核对返回字段、版本、运行依赖与非零退出码。

验收：Agent 不读 App 源码即可知道命令、操作字段及读写步骤；Mode 真实文件、脚本和图可读，越界链接不可读。

## 任务二：收束写入门控

涉及：`management.py`、`sync.py`、`portable.py`、`workspace.py` 及门控测试。

1. 复现旧同步坏图、SOURCE-only 坏图、新目标父目录链接与视图文件链接。
2. 各正式写入口复用结构和真实渲染门禁；加 Environment 级跨进程协作锁及指纹复核。
3. 测试并发、渲染期变更、失败回滚；所有测试在隔离目录。
4. 独立审查复验最终候选的 Secret 边界、稳定修复路径、完整 Mode 资产往返、恢复路径碰撞和 Windows 换行往返；不以实现者报告替代验收。

验收：非法内容零正式写入；同版本并发提交不能互相覆盖；失败返回定位，不伪称脚本或业务已运行。

## 任务三：App 同源与等待收敛

涉及：`desktop/bridge.cjs`、`main.cjs`、`src/App.jsx`、图编辑组件及 Node 测试。

1. 先复现错误详情丢失和已有 Mermaid 的双编辑路径问题。
2. 保留结构化错误；普通保存只做一次核心验收，保留需用户决策的预览。
3. 原生图通过原生编辑器修改；成员管理不得伪装为 Mermaid 关系编辑。

验收：失败保留草稿；保存回读一致；全图型渲染和基础流程图可视编辑的能力分别声明。

## 任务四：架构拆分、同步与交付

涉及：`docs/asl-architecture-views.md`、`docs/architecture/`、产品决策、Skill Library 入口文档、机械发布检出。

1. 先写分块、链接和图总数保持的失败测试。
2. 专项内容迁入单独文件，总览保留导航、兼容锚点和唯一当前状态；不维护重复副本。
3. 运行文档链接检查、协议校验、核心与桌面回归、真实离线图渲染。
4. 按受管文件清单机械同步发布检出；内容版引用同一 CLI 与协议。打包排除秘密、缓存和个人偏好，核对包与源码内容。

验收：架构与专项视图分块可读、旧链接可定位；框架/内容版事实一致。尚未完成的冷启动、任意图拖拽、真实宿主会话和签名发行不标为完成。
