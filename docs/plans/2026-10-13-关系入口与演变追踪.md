# 关系入口与演变追踪

## 用户取舍与范围

- 关系与影响先完成位置、范围和视觉交互设计，提供可交互预览。视觉质量和产品感由具体稿件判断，尚不接入正式导航。
- 演变页可以实施：沿用现有时间轴、同一 Mermaid 画板和 Git 历史，补选中版本的可读变更依据与说明编辑。
- Candidate／Trial 保留内容与校验，不新增前端栏目、列表或阶段面板。
- 保持现有苹果风格、业务 Mode／Skill 和原生保存门控。不新增图引擎、时间轴包、模型执行器或数据库，不修改真实业务内容。

## 设计方向

关系入口放在技能标题附近，默认为轻量“使用关系 · 4 个模式”。展开只看当前技能的一跳关联：中心是这份完整技能，关联的是实际使用它的 Mode；依赖单独说明，不与作者的工作协作线混合。当前 Mode 有明确选中态，其他 Mode 保持中性。没有关系给出文字，无须空图；关系较多时局部展开／滚动，不铺满全库。编辑时展示实际影响对象，浏览时不常驻警告。

演变页保持画板为主体，下方时间轴控制版本；右侧窄栏承载所选版本的主题、实际加入／移出、用户或 Agent 已写的变化说明。选中版本、画板和说明保持同一修订号。时间轴按版本顺序排列，邻近记录显示日期和简短主题，保留完整范围滑块、上一版／下一版及受控回放。缺少原因时准确显示未补充，不把结构恢复或会话退出当成任务效果证据。

动效焦点是版本变化时同身份节点的空间连续性，复用现有 FLIP／Web Animations；说明栏只做短暂淡入。用户仍能即时选择和停止。减少动态效果时保留选中、颜色与文本反馈，不移动节点。

## 已核查的参考

- [vis-timeline 文档](https://visjs.github.io/vis-timeline/docs/timeline/)：时间项选择与可见范围；只参考交互思路。
- [vis-timeline 开源仓库](https://github.com/visjs/vis-timeline)：完整可移动／缩放时间轴，功能明显超出本轮需要，因此不安装。
- [Motion 布局动效](https://motion.dev/docs/react-layout-animations)：跨布局保持身份连续；当前项目已有对应的轻量节点动效，不新增 Motion 依赖。

GitHub CLI 本轮网络连接失败，公开文档及仓库通过浏览工具完成读取。没有安装或复制这些项目代码。

## 实施与验收

1. 关系入口：生成独立交互设计预览，使用真实 `usedBy` 数据 → 核对默认／展开／编辑影响、1320／920 窗口及键盘关闭；不写真实库。
2. 演变追踪：先补说明写入边界与版本选择的失败测试，再接现有 CLI notes 和前端 → 验证旧说明指纹冲突、取消、草稿保护、说明与画板同版本、恢复仍只改 Mode 结构。
3. 视觉收束：一轮成组截图，集中修正，至多一轮确认 → 实际运行 Impeccable 检测，保留截图与检查记录；不以机械扫描代替视觉判断。

本轮不推送、不替换桌面发行包，先交付本地设计稿与开发版演变页。
