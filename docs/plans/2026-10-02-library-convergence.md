# 模式库身份与工作区收敛实施计划

**目标：** 修复选择库导致侧栏重排的问题，清楚对应本地工作库与 GitHub 来源，保全个人修改后整理历史入口。

**架构：** 复用现有本地路径身份、偏好、库发现与云端来源接口；不增加业务数据库，不按同名合并文件。用户要求唯一本地内容真源对应 GitHub，不强制保留个人库与发布副本两套体系；框架代码与技能内容仍分开。真实删除遵守根目录精确路径确认门禁。

**技术：** Electron / React / Node 测试与现有 Harness CLI。

## 1. 先核对再清理

- 比较旧写作副本、个人库、公开库的 Git 状态、逐文件内容与入口引用。
- 保留独有内容；核对使用中的投影后才能移除源目录。无关写作、案例、账号和用户未提交文件不清理。
- 验收：清理清单能说明每个目录的用途、引用、独有内容及操作边界。

## 2. 导航修复

- `desktop/library.cjs`：打开已有库只改最近使用状态，不重排注册顺序。
- `desktop/src/SourceLibrary.jsx`、`desktop/src/App.jsx`：已发现与当前目录按同一稳定身份合并，模式属于确定的库；本地与 GitHub 来源可辨识。
- `desktop/test/`：先复现打开库前后排序变化，再覆盖同名不同根目录、异步回读、当前目录内容更新。
- 验收：三库交替与快速切换不换位，节点读取路径与所选库相同。

## 3. 收敛实际入口

- 本地工作真源选定后，备份现有偏好并撤下历史工作入口，不擅自合并冲突业务文件。
- 建议保留已有 GitHub 历史的内容检出，先合入个人库的有效差异；云端关联不意味着自动上传个人资料，或自动覆盖未提交的本地修改。
- 删除先提供精确路径、理由与影响，确认后检查绝对路径边界执行。

## 4. 交付验证与文档

- 运行桌面测试、构建及隔离 Electron 导航回归。
- 更新根 `WORKSPACE.md`、产品决策与总体/专项视图，分别记录开发完成、部署状态和仍需确认的清理。
- 不把当前用户其他改动混入提交；不自动推送个人资料。

## 5. 已确认的实施顺序

用户已确认迁移到 `libraries/agent-skill-library`，不再维护两份活动内容库。

1. 备份三个库（含 Git 历史、未提交及忽略文件），逐文件哈希核对；在隔离候选里三方合并旧写作改动，保留目标库较新的声明。
2. 合入个人库独有投资图和归档；投资图直接使用 Mermaid 流程图、时序图、状态图、思维导图，使用真实技能 ID，不引入新的执行器或场景对象。
3. 候选运行 `workspace.validate` 和全部图实际渲染，再采用内容；迁移受管入口和 App 偏好，非受管内容不改。账号和 GitHub 上传不在范围内。
4. 用隔离桌面验证各图切换、缩放、全屏、原文编辑和保存；可视编辑按真实能力单独验收，不把多图型渲染等同于任意拖拽编辑。
5. 更新总览、专项视图和根索引；旧目录冻结归档，不未经精确路径确认物理删除。

## 6. 统一视觉与可读性补充验收

- 四种图型共用既有 Mermaid 渲染、字体、浅蓝配色、线条和画布，不另建视觉体系。
- 普通窗口截图检查默认字号、标签越界与拥挤程度；全屏、缩放、选技能与原文保存逐图验证。
- 先记录失败再修正：流程图自动缩放后约 9 px、思维导图默认分组标签错位；改为默认原始字号，主动适应宽度保留总览，按原生节点形状校正文字锚点。
- 不把所有图型渲染通过说成任意图型均已支持自由拖拽或原位连接。
