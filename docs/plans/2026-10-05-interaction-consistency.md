# 工作区操作一致性实施计划

**目标：**同一类对象具有一致、可恢复的操作；拖动宽度与画板交互不因切页、保存或重新打开失效。

**架构：**沿用现有 React 页面、PanelResize、原生 Mermaid 和 CLI 校验；不新建画布引擎、数据库或交互框架。只修改 App/框架和临时测试数据，不修改真实 Skill、Mode 或账号配置。

**技术：**React、CSS、Electron、现有 Playwright / Node 测试。

## 操作边界

| 对象 | 预期操作 | 保护条件 |
| --- | --- | --- |
| 主导航、技能导览、文件目录、模式编辑器技能栏 | 拖动边界调宽；双击复原；重开记忆 | 宽度只是本机界面偏好；窄窗口保留正文可用空间 |
| 本地工作库 | 右键新建工作库、打开已有库 | 用户选择首个有效 Mode，通过现有完整包门控复制；保留源内容、不假造技能、不覆盖现有目录 |
| Mode | 右键新建同库同级 Mode、打开、编辑、复制、归档 | 新建不是子项目或子图；沿用已有写入门控和确认 |
| Mode 内画板 | 新建图、添加技能节点、拖动、连接、编辑、移除 | 只改组织；移出节点不删除技能正文 |
| 云端来源 | 查看、刷新、移除连接 | 不删除本地库或上游仓库 |
| 退出编辑、切换对象 | 未保存时确认是否放弃；恢复阅读对象与位置 | 取消保留草稿，确认允许丢弃，不自动保存；禁止过期响应覆盖新状态 |

### 推进顺序

1. 先做 `harden`：G01 草稿保护、G02 异常恢复、G03 连接记录，复用现有边界与确认契约。
2. 再做 `shape / harden`：G05 对象右键、G06 阅读位置、G07 同内容入口、G08 就地重试；每类只确定一套行为并检查所有调用点。
3. 做 `optimize`：G09 与画板连续保存。先拆分等待、验证和回读成本，再优化实际瓶颈。
4. 做 `adapt / layout`：G04 缩放回流、G10 适用分栏；使用真实长文本验收。
5. 最后一次有界 `polish`：确认同类操作、数值、对齐、悬浮层和返回连续性一致，不改现有视觉方向。

- 60 节点／59 连线线性图首次打开约 1064 ms，再次约 630 ms；观察到 51–271 ms 的 renderer 长任务。仅为两次暖机示例，不是大型真实库、冷机或网络基准，也不能从总耗时推断每一次点击卡死。

- 150% 缩放下所测右键菜单仍在视口内，无越界；本轮不是所有屏幕／菜单都通过。
- Impeccable detector 的 `width` 转场命中是现有缩小浮图动效，未证明由它造成掉帧，不能据此删除用户要求的交互。
