# 阅读、恢复与视觉校准实施计划

## 已确认范围

用户确认优先推进画板阅读、配置冲突恢复和真实任务验收；可使用 Taste 与 Impeccable，参考 Apple／Google 设计。依赖用户反馈的整体操作路径调整留待后续。

共享约定：`/Users/blazezhang/.codex/SHARED-WORK-PILOT.md`。只改变 App 与必要的验收材料；现有 Mode、Skill 正文、原生插件和业务架构保持原有内容。

## 设计取舍

当前已存在蓝色品牌与单一浅色界面。本轮将其收束为浅色中性工作台，保留蓝色作为操作强调；减少装饰渐变与模糊，统一文字、表面、边框和状态角色。采用系统字体与已有 Lucide 图标，不换前端框架或增加动画依赖。视觉决策记录在 DESIGN.md。

画板提供全图概览、缩放比例和原始大小阅读；清楚区分看关系与读节点，不改作者图。配置冲突提供已有的项目范围／目录选择路径，不添加覆盖现有内容的捷径。

## 执行与验证

1. 先补画板与冲突的失败验收，再完成最小实现；验证初次适应、恢复视角、键盘操作及冲突保护。
2. 校准已有颜色角色和常用控件；在真实库的隔离副本检查 1320／920 像素、对比度、焦点、错误与空态，并实际运行 Impeccable 检测。
3. 将真实 Product Lab 投影到独立临时项目，使用现有原生 Codex 的模型与账号完成一次仅依赖本地材料的小任务；核对技能读取、事实依据、未知项和输出文件。禁止联网、安装、发布或修改长期业务内容。
4. 运行相关模块与原生流程验收；构建本机 App、核对签名与资源，再更新桌面入口和使用说明。按目标分别记录中文、带日期时间的 Git 提交，不对外推送或发布。

## 暂不扩展

整体导航重排、新的主题选择器、自动培养、第二调度器和反馈闭环不进入本轮。真实任务若被模型连接或认证阻断，记录准确边界，不把终端打开当作任务成功。
